# Security

Report vulnerabilities using **Security → Report a vulnerability** on this GitHub repository once private vulnerability reporting is enabled. Do not include credentials, raw input events, personal daily history, or nearby Bluetooth addresses in public issues. If private reporting is unavailable, open an issue asking for a private contact without disclosing exploit details.

Only the current version is maintained. Runtime dependencies are pinned. CI audits runtime and development packages, including transitive dependencies, on pull requests and weekly; updates still need review and testing.

The trusted boundary is your local desktop user account. This application can observe X11 device events or, with explicitly granted access, Wayland seat devices through Linux evdev and, when explicitly configured, control a compatible desk. Aggregates stay local. There are no remote control endpoints, HTTP clients, account credentials, or telemetry. The Bluetooth socket and status files are private to the owning user. Programs already running as that user are trusted.

The optional Wayland udev rule grants raw keyboard/mouse/touchpad access to the active local seat user, including other programs running as that user and password-field input. Those ACLs remain while locked and do not revoke already open descriptors. work-habbits runs without root, opens devices read-only without grabbing them, closes them while locked/inactive, and discards summaries when session verification fails. It never installs the system rule automatically or changes input-group membership. See README.md for opting in and revoking access. Review session/seat isolation, permission failures, hotplug, queue overflow, and the absence of raw event logging when changing this backend.

The **Enable Wayland input** action explains this permission and then requests normal administrator authorization through `pkexec`. The standalone `wayland_setup.py` helper runs with isolated system Python, accepts no paths or rule contents, writes only the fixed application rule atomically, rejects conflicting files/symlinks, and applies it to existing devices through fixed udev commands. It never reads input or installs a passwordless polkit policy or root service. Cancelling/denying authorization never retries the privileged operation automatically. Setup tests redirect the rule into a temporary directory and mock all udev calls; they never elevate privileges or change system permissions.

Check a proposed Bluetooth change for unintended motion, broad device discovery/connection, timeout/cancellation paths, and preserving STOP behavior. Validate hardware compatibility and keep a physical stop control available. See README.md for protocol limits and disconnect behavior.
