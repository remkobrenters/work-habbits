# Work Habbits v1.3.0

This release adds physical keyboard/mouse counts and hand reminders on GNOME Wayland, with guided input permission setup in the panel menu.

## Changes

- Select Linux evdev automatically on Wayland and retain X11 RECORD on Xorg. Counts cover physical device activity across native Wayland and XWayland applications.
- Offer **Enable Wayland input…** in the Hands card when device permission is missing. Explain the permission, request normal administrator approval, apply access to current devices, and resume tracking automatically. Cancelling never repeats authorization prompts; disconnected devices do not trigger setup.
- Restrict collection to the owning user's active, unlocked local Wayland session and its seat. Close readers and discard summaries when session verification fails, on pause, or after device errors. Retry permission failures and reconnects without reporting partial device coverage as complete.
- Preserve anonymous aggregate summaries: key presses, physical clicks, sampled motion, and hand activity timestamps. No raw input, keycodes, typed text, or coordinates are emitted or stored.
- Run the Wayland reader with system Python so input tracking survives a Python upgrade. Repair missing pip on reinstall and restore previously installed Bluetooth dependencies for the current Python.
- Add regression coverage for device decoding, repeats, scrolling, touchpad activity, reconnects, queue overflow, session/seat isolation, permission setup, cancellation, and extension cleanup. Update installation help, privacy documentation, and rendered previews.

## Upgrade

From the extracted source archive or updated checkout, run as your normal user in a local GNOME desktop terminal:

```bash
./install.sh
```

Existing settings, history, and a previous Bluetooth installation are preserved. First-time Bluetooth users should use `./install.sh --bluetooth`.

Log out and back in once to load the updated extension. You can keep working and defer logout until convenient. On Wayland, restarting GNOME Shell while preserving existing windows is not supported, and toggling the extension does not reload cached JavaScript. On Xorg, **Alt+F2 → restart → Enter** also reloads Shell.

After login, open the panel menu and choose **Enable Wayland input…** if offered. Review the explanation, choose **Enable**, and approve the system administrator dialog. This permission step applies immediately; no terminal commands, additional logout, or reboot are required. An existing installation without this update must first be updated; older releases do not update themselves.

## Permission and counting limits

The optional system udev rule grants active local seat users access to keyboard, mouse, and touchpad devices. Other programs running as those users gain raw input access too, including password-field input; the ACLs remain while locked. Work Habbits itself stops collection while locked. The normal installer does not grant this permission, add input-group membership, install a passwordless policy, or run a root input reader. See the README for the manual fallback and permission removal.

Wayland counts describe physical device activity before compositor remapping. Touchpad taps, on-screen keyboard input, and compositor-generated clicks are not physical click counts. Touchpad contact and finger motion count as hand activity; ordinary mouse motion alone does not. Media-key and Super+L exclusions use Linux physical key codes.

## Validation and compatibility

Local quality gates include style/security lint, syntax checks, strict schemas, Python and JavaScript behavior tests, isolated install/uninstall tests, GJS settings/storage checks, udev rule verification, dependency auditing, and source packaging. A host-side run also passed the Unix-socket integration test. The dependency audit found no known vulnerabilities in the runtime or development requirements. The release workflow repeats checks and auditing before publication. CI and release package setup now run noninteractively with bounded network retries/timeouts and a step limit after an Ubuntu runner stalled during environment setup.

GNOME 46–50 on Wayland is implemented, with full desktop and hardware verification still pending. The administrator dialog, live input devices, and lock/TTY transitions have automated coverage with external I/O simulated; they have not been verified on a real desktop in this release session. The active desktop was left running to preserve open windows. Bluetooth protocol and movement behavior are unchanged. README previews use sample data and are not desktop screenshots.
