# Work Habbits v1.3.1

Fix input startup and menu updates on GNOME 50. v1.3.0 called the removed `Meta.is_wayland_compositor()` API, then showed the misleading “Input reader unavailable; run ./install.sh again” message.

## Changes

- Treat GNOME 50's missing compositor query as Wayland. Earlier supported GNOME versions continue to use the query for Xorg/Wayland selection.
- Use the compatibility check for helper startup, backend selection, permission setup and menu rendering.
- Stop partially started helpers and show the actual startup error instead of always recommending reinstallation. Clear stale setup messages so they cannot hide that error.
- Cover the removed API in model/UI regression tests. Add a CI and release gate using actual GNOME 50 Meta/GIO libraries, plus an isolated full-Shell smoke test with generated input.

## Upgrade and current-session recovery

Run `./install.sh` as your normal user. Settings and history are preserved. The fixed JavaScript loads at your next login; you can defer logout until convenient.

To restore an already-running v1.3.0 session without closing your windows, press **Alt+F2**, enter **lg**, then paste this into Looking Glass and press Enter:

```javascript
(() => { Meta.is_wayland_compositor = () => true; const e = Main.extensionManager.lookup('work-habbits@local').stateObj; e.disable(); e.enable(); })()
```

Press Escape and open the panel menu. Choose **Enable Wayland input…** if offered and approve the normal permission explanation and administrator dialog. The shim lasts only for the current Shell session; installed v1.3.1 handles future sessions without it.

## Validation

The regression test reproduced the v1.3.0 startup failure before the fix and passes afterward. Tests using installed GNOME 50.1 libraries verify the missing-API fallback and native GIO/Python startup. A separate headless GNOME 50.1 session passes native menu rendering, permission explanation/cancellation, generated input counts, manual posture and pause/resume. The current-session workaround also passes that scenario using the exact v1.3.0 extension.

Standard quality checks, dependency auditing and source packaging run before publication. Physical evdev event collection and actual polkit authentication remain unverified in this release session; tests use generated input and never alter system input permissions. The real desktop was left running.
